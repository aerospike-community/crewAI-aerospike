## 개요

CrewAI 메모리는 레코드를 Aerospike에 보관할 수 있습니다. 시작 시 스토리지 팩토리를 한 번 등록한 다음, `aerospike://host:port/namespace` 형식의 스토리지 스펙으로 백엔드를 선택합니다. 그 밖의 스토리지 스펙은 계속 내장 백엔드를 사용합니다. 이 페이지는 아무것도 없는 상태에서 몇 분 안에 메모리를 저장하고 다시 불러오는 데까지 안내합니다. 데이터 배치의 이유와 검색 비용이 궁금하다면 [Aerospike 메모리 설계](/edge/ko/learn/aerospike-memory-design)를 읽어 보세요.

<Warning>
이 빠른 시작은 인증이 설정되지 않은 서버를 실행하며, 스토리지 스펙은 자격 증명을 받지 않습니다. 로컬 개발용으로만 사용하고, 포트는 루프백 주소에만 게시하며, 공유 서버는 항상 사설 네트워크에 두세요.
</Warning>

## 사전 요구 사항

- Python 3.11 이상.
- Docker.
- 다른 `Memory` 사용 때와 같은 방식으로 설정된 임베딩 제공자. 기본 임베더는 `OPENAI_API_KEY`가 필요하며, 다른 제공자를 쓰려면 `Memory`에 `embedder=`를 전달하세요.
- 벡터 값을 지원하는 클라이언트. 임베딩은 네이티브 벡터 값으로 저장되므로 Aerospike 클라이언트가 이를 지원해야 합니다. 프로젝트에서 이에 의존하기 전에 [설계 문서](/edge/ko/learn/aerospike-memory-design)의 '제한 사항' 아래 '클라이언트 요구 사항' 절을 읽어 보세요.

## 서버 시작

Aerospike 서버 이미지를 실행합니다. 이 서버에는 인증이 없으므로 포트는 루프백 주소에만 게시됩니다.

```bash
docker run -d --name crewai-aerospike --ulimit nofile=15000:15000 -p 127.0.0.1:3000-3002:3000-3002 aerospike/aerospike-server
```

서버가 시작되는 데 몇 초가 걸립니다. 이미지의 기본 구성에는 `test`라는 네임스페이스가 있으며, 아래 예제가 이를 사용합니다. 다른 네임스페이스를 사용하려면 스펙의 마지막 부분을 바꾸세요.

## 설치

```bash
pip install "crewai[aerospike]"
```

`aerospike` extra는 `aerospike-sdk` 클라이언트와 `numpy`를 설치하며, Python 3.11 이상이 필요합니다.

## 사용하기

`Memory`를 만들기 전에 팩토리를 등록하세요. 등록은 이후에 생성되는 `Memory` 인스턴스에만 영향을 줍니다.

```python
from crewai import Memory
from crewai.memory.storage.aerospike_storage import aerospike_storage_factory
from crewai.memory.storage.factory import set_memory_storage_factory

# Register once at startup. Specs that do not start with aerospike:// are left
# to the built-in backends.
set_memory_storage_factory(aerospike_storage_factory)

memory = Memory(storage="aerospike://127.0.0.1:3000/test")

memory.remember(
    "The Q3 launch is planned for the first week of October.",
    scope="/demo/planning",
    categories=["launch", "schedule"],
    importance=0.8,
)

matches = memory.recall("When is the launch?", scope="/demo", depth="shallow")
for match in matches:
    print(f"{match.score:.2f}  {match.record.scope}  {match.record.content}")
```

범위, 카테고리, 중요도를 명시적으로 전달하고 `depth="shallow"`를 사용하면 두 호출 모두 LLM이 필요 없으며 임베더만 사용됩니다. 이를 생략하면 `Memory`가 다른 백엔드와 마찬가지로 분석 모델로 추론합니다.

## 확인

스크립트를 실행하면 불러온 메모리마다 점수, 범위, 내용이 한 줄씩 출력됩니다. 예를 들면 다음과 같습니다.

```text
0.74  /demo/planning  The Q3 launch is planned for the first week of October.
```

점수는 `recall`이 보고하는 종합 관련도 점수이므로 정확한 값은 사용하는 임베더에 따라 달라집니다. 이 줄이 나타나면 레코드가 서버에 기록되었고 벡터 검색으로 다시 읽혔다는 뜻입니다.

작업이 끝나면 `docker rm -f crewai-aerospike`로 서버를 중지하고 제거하세요.

## 문제 해결

**연결이 거부됩니다.** 백엔드는 `Memory`를 생성할 때 연결하므로 오류도 그때 발생합니다. `docker ps`로 컨테이너가 실행 중인지, 위 명령처럼 포트가 게시되었는지, 스펙의 호스트와 포트가 일치하는지 확인하세요. 컨테이너를 시작한 뒤 몇 초 기다렸다가 다시 시도하세요.

**`EmbeddingDimensionMismatchError`가 발생합니다.** 스토어는 처음 본 임베딩의 길이를 기억하며, 다른 길이를 반환하는 임베더는 거부됩니다. 스토어를 만든 임베더를 사용하거나 스토어를 초기화하세요. [설계 문서](/edge/ko/learn/aerospike-memory-design)의 '임베딩 차원' 절을 참고하세요.

**클라이언트를 설치하라는 `ImportError`가 발생합니다.** 코드를 실행하는 환경에 extra가 없습니다. `pip install "crewai[aerospike]"`로 설치하세요.

**스토리지 스펙을 언급하는 `ValueError`가 발생합니다.** 스펙은 `aerospike://host:port/namespace` 형식이어야 하며 뒤에 `?set_prefix=NAME`을 붙일 수 있습니다. 스펙에 포함된 자격 증명과 그 밖의 쿼리 키는 거부됩니다.
